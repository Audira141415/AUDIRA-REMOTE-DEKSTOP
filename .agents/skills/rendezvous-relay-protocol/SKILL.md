# Rendezvous & Relay Protocol Skill

This skill explains the custom networking protocol used by AUDIRA Remote Desktop to discover peers, perform NAT hole punching, and fallback to encrypted relay servers.

## 1. Key Protocol Components
- **`src/rendezvous_mediator.rs`**: Core client mediator communicating with `hbbs` (Rendezvous) and `hbbr` (Relay).
- **`libs/hbb_common/src/socket_client.rs`**: Low-level framing and socket management.
- **Ports**:
  - `21115 TCP`: NAT type probe
  - `21116 TCP/UDP`: Heartbeat, registration, and hole punch signaling
  - `21117 TCP`: Encrypted relay transport

## 2. NAT Traversal & Hole Punching Flow
1. **Heartbeat:** Periodically send UDP datagrams to `hbbs:21116` to keep NAT mapping alive in the local router.
2. **Punch Request:** When Client requests connection to Host, `hbbs` sends `PunchHoleRequest` to Host containing Client's public IP:Port.
3. **Simultaneous UDP Transmit:** Both Client and Host send UDP probe packets to each other's discovered public endpoints.
4. **Relay Fallback:** If no response is received within 3 seconds (e.g. Symmetric NAT detected), both peers establish TCP connections to `hbbr:21117` with a matching connection token.

## 3. Self-Hosted Server Configuration
To point AUDIRA Remote Desktop to a private rendezvous/relay cluster:
1. Configure `KEY_CUSTOM_RENDEZVOUS_SERVER` in `libs/base/src/config/keys.rs` with the server domain.
2. Set `KEY_SERVER_KEY` with the public key found in `id_ed25519.pub` generated by `hbbs`.
